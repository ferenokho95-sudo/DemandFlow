# DemandFlow — Demand Forecasting Platform

Учебный MLOps/DataOps-проект для e-commerce: загрузка ежедневных продаж, проверка качества данных, витрина признаков, обучение, выбор модели, публикация прогнозов и мониторинг. Все демонстрационные продажи синтетические. Коммерческий опыт и production-эксплуатацию проект не имитирует.

## Начало работы

Откройте **START_HERE_RU.md**. На Windows можно запустить **start_local.bat** с Python 3.11 или **start_docker.bat** с работающим Docker Desktop.

## Возможности

- CSV-контракт: `date,product_id,units`, одна строка на товар и день.
- Валидация: даты, пропуски, дубликаты, непрерывная история, отрицательные и бесконечные продажи.
- Признаки: прошлые продажи за 1/7 дней, средние за 7/28 дней, календарь и товар.
- Ridge и сезонный baseline. Выбор по MAE на последних 14 днях, прогноз рекурсивный без подглядывания в фактические продажи holdout-периода.
- После выбора модель обучается на всей доступной истории. Горизонт 1–60 дней.
- Версии модели, снимки исходных данных, SHA-256 и отчёт о каждом запуске.
- API с переключением на новый успешный запуск одной транзакцией; неудачный запуск сохраняет предыдущий опубликованный прогноз.
- Сверка ранее опубликованных прогнозов с новыми фактическими продажами; MAE и WAPE.
- Полный режим: PostgreSQL, ClickHouse, MinIO, MLflow, Airflow, Prometheus.
- Локальный режим: тот же расчётный код, SQLite и файлы; дополнительные сервисы не требуются.

## Команды

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m demandflow.cli sample
python -m demandflow.cli run --csv data/sales.csv --horizon 14
python -m uvicorn demandflow.api:app --host 127.0.0.1 --port 8000
```

`sample` перезаписывает CSV синтетическими данными. Не выполняйте эту команду поверх собственных продаж.

```bash
python -m pytest -q
docker compose up --build -d
docker compose run --rm pipeline
docker compose down
```

## Хранилища

PostgreSQL хранит авторитетный снимок продаж `sales_daily` и сведения `forecast_runs`. CSV — полный актуальный снимок, а не пачка приращений. ClickHouse хранит версии прогнозов `forecasts`, фильтруйте по `run_id` опубликованного отчёта. MinIO — снимок продаж, витрина, модель и отчёт `demandflow/runs/<run_id>/`. MLflow — параметры, метрики и артефакты экспериментов; его метаданные лежат в PostgreSQL, артефакты — в отдельном каталоге общего volume.

Локальный SQLite хранит реестр запусков и указатель опубликованной версии для API. Здесь это осознанное упрощение: экземпляр API один, общая файловая система локальная. Масштабирование потребует перенести реестр в PostgreSQL.

## Автоматизация

DAG `demandflow_daily` запускается в 06:00 UTC, изначально на паузе. Он читает `/data/sales.csv`, выполняет переобучение и публикует прогноз. Новые продажи необходимо доставлять в CSV из реального источника. Генератор не подставляет вымышленные новые факты в ежедневный процесс. DAG содержит одну Python-задачу, охватывающую полный цикл под блокировкой; внутренние стадии видны в коде и отчётах.

CI GitHub Actions запускает тесты, проверяет Compose, собирает оба Docker-образа и выполняет полный pipeline с проверкой API. Этот workflow выполнится после загрузки проекта в GitHub; здесь он ещё не запускался. Автоматический деплой на внешний сервер не настроен: нужны выбранный сервер, секреты и политика релизов.

## Границы проекта

Это воспроизводимый учебный стенд. Docker-сервисы требуют ресурсов и первоначальной загрузки образов. В приложении нет авторизации, внешнего источника продаж, GPU, Kubernetes и автоматического отката качества между разными датасетами. Новая модель сравнивается с baseline на текущем holdout; между запусками действует защита от технически неуспешной публикации. Пороги алёртов демонстрационные. Прогноз не учитывает дефицит товара, акции и цену; наблюдаемые продажи могут отличаться от истинного спроса.

Ограничения распределённых записей, восстановление и перевод в production описаны в `docs/OPERATIONS_RU.md`.
