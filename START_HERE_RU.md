# Как запустить DemandFlow

## Вариант 1. Простой запуск на Windows

1. Установите Python 3.11 с python.org, при установке включите Python Launcher и добавление в PATH.
2. Полностью распакуйте архив в папку, например `C:\Projects\DemandFlow`. Не запускайте файлы внутри ZIP.
3. Дважды нажмите `start_local.bat`. Первый запуск установит зависимости через интернет.
4. После обучения откроется http://127.0.0.1:8000. Если страница открылась раньше сервера, обновите её через несколько секунд.
5. Окно командной строки оставьте открытым. Для остановки нажмите Ctrl+C.

В комплекте есть демонстрационный CSV: 12 товаров, 240 дней. Для нового синтетического набора с датами до вчерашнего дня выполните `.venv\Scripts\python.exe -m demandflow.cli sample`, затем снова запустите bat. Это удалит предыдущий CSV; сохраните собственные данные отдельно.

Локальный запуск выполняет проверки, обучение и прогноз и открывает панель. Airflow, PostgreSQL, ClickHouse, MinIO и MLflow включаются в полном варианте ниже.

## Вариант 2. Полный Docker-стенд

Нужны Docker Desktop с Linux-контейнерами/WSL2, интернет и ориентировочно 8 ГБ доступной оперативной памяти для стенда, лучше 12 ГБ. Это ориентир, ресурсные замеры не проводились. Освободите несколько гигабайт для образов.

1. Запустите Docker Desktop и дождитесь готовности.
2. Откройте `start_docker.bat`, дождитесь загрузки, сборки и расчёта.
3. Откройте сервисы:

| Сервис | Адрес | Вход по умолчанию |
|---|---|---|
| Панель | http://127.0.0.1:8000 | Без входа |
| API Swagger | http://127.0.0.1:8000/docs | Без входа |
| Airflow | http://127.0.0.1:8080 | admin / admin_local |
| MLflow | http://127.0.0.1:5000 | Без входа |
| MinIO | http://127.0.0.1:9001 | demandflow / demandflow_local |
| Prometheus | http://127.0.0.1:9090 | Без входа |

4. В Airflow найдите `demandflow_daily`, включите переключатель и нажмите Trigger DAG для ручного запуска. По расписанию DAG работает в 09:00 по Москве (06:00 UTC).

Сервисы по умолчанию доступны только с этого компьютера. Учётные данные демонстрационные; `.env.example` можно скопировать в `.env` и изменить до первого запуска. Пароль Airflow задаётся отдельно в `compose.yaml` в `airflow-init`.

Повторный расчёт из терминала в папке проекта:

```powershell
docker compose run --rm pipeline
```

Остановка с сохранением результатов: `docker compose down`. Следующий запуск: `docker compose up -d`.

## Подставить свои данные

Замените `data/sales.csv`. Формат:

```csv
date,product_id,units
2026-01-01,SKU-001,18
2026-01-02,SKU-001,0
2026-01-03,SKU-001,21
```

Пример показывает только формат. Для каждого товара нужны минимум 70 дней подряд с одинаковой конечной датой. Отсутствие продаж обозначайте `0`. Пропущенную выгрузку нельзя автоматически считать нулевыми продажами. Файл должен содержать всю историю, которую требуется использовать. Для нескольких транзакций одного товара за день сначала агрегируйте количество.

После обновления CSV повторно запустите pipeline. API автоматически начнёт выдавать новый успешный прогноз.

## Если возникла ошибка

- Окно bat не закрывается: скопируйте сообщение об ошибке над `pause`.
- `py` не найден: установите Python Launcher либо запускайте команды через установленный `python`.
- Порт занят: завершите локальный сервер перед Docker-запуском либо измените порт слева в `compose.yaml`.
- `No published forecast`: ещё не выполнен успешный pipeline.
- `stale_data`: последняя дата продаж старше двух дней; замените демонстрационные данные свежими.
- Ошибка Docker: `docker compose ps -a`, затем `docker compose logs --tail 100 <сервис>`.
- После изменения пароля в `.env` существующая PostgreSQL сохраняет старый пароль. Сначала верните старый пароль или измените его средствами базы, не удаляйте данные ради смены пароля.
